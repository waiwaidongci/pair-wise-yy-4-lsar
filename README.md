# 水下考古潜水记录

直接打开 `index.html` 使用。点击平面图添加标记，支持筛选、编辑、撤掉、潜次时间线、潜次管理，以及分队船与岸基整理室之间的**离线合并**。

## 离线合并怎么用

1. 各设备离线记录（分队船 / 岸基整理室互不依赖，各记各的）。
2. 回码头后：在一台设备点「导出批次」，把生成的 JSON 文件拷到另一台，点「导入批次」。
3. 两边改过同一字段的冲突会在「同步」页挂起，人工选「保留本地 / 采用对方」，处理结果随下次导出同步回去。
4. 批次可互相转发：岸基收到的船上操作，会随岸基自己的导出一起带给其他分队船。

## 合并规则

- 每条改动（潜次/标记的新增、修改、撤掉）是一条操作，携带**设备号、基准版本（版本向量）、操作号**；
- **同一操作号重传只认首次结果**：同一批次或同一操作重复导入不会重复落账；
- **撤掉留下墓碑**：已撤掉的标记/潜次不会因对方迟到的编辑重新出现，删除先到时连迟到的创建也会被挡住；
- **同字段并发修改**：两份现场值都保留并挂起，人工解决后生成解决操作收敛；两边改成同一个值不算冲突；
- **导入可断点续传**：批次逐条落盘，导入中途崩溃，重启后自动从断点续导未完成批次；
- **旧数据升级补来源**：旧版 `zfl30Marks` 数据首次启动自动迁移为操作并补录来源（原数据备份在 `zfl30Marks.migrated`）；
- 操作按设备序号缺号暂存：乱序到达的批次，前序补齐后自动落账。

## 代码结构

- `js/sync.js` — 合并引擎（操作日志、版本向量、墓碑、冲突挂起、批次续导、旧数据迁移），浏览器与 Node 通用；
- `js/app.js` — 界面（标记/潜次/同步三个页签）；
- `test/sync.test.js` — 合并规则测试。
